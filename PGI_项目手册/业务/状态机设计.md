# 状态机设计

本文档详细阐述 PGI 系统的 9 个状态机设计、状态机引擎原理、Action 枚举、自动流转定时任务和使用示例。适合开发人员理解"状态怎么流转、谁来触发、怎么校验"。

## 一、为什么需要状态机

### 1.1 传统状态管理的问题

传统系统的状态字段常常被人工直接 `UPDATE status='X'`，导致：

| 问题 | 后果 |
|------|------|
| 状态跳步 | 如未开标就中标，业务逻辑混乱 |
| 非法回退 | 如已中标退回投标中，数据错乱 |
| 流程卡死 | 状态卡在某个中间态无法继续 |
| 缺乏审计 | 谁改的、什么时候改的、为什么改，无从追溯 |

### 1.2 状态机解决方案

本系统通过 **`StateMachineEngine`** 统一管理状态流转：

```
每次状态跳转都经过：
当前状态 + 操作 + 前置校验 → 下一状态

任何一环不通过 → 抛 IllegalStateTransitionException
```

**核心原则**：禁止直接 update status，必须经过 `StateMachineEngine.transition()`。

## 三、状态机引擎设计

### 3.1 引擎结构

```
ruoyi-common/src/main/java/com/ruoyi/common/statemachine/
├── StateMachineEngine.java                  # 泛型状态机引擎
├── StateTransition.java                     # 状态跳转定义：from→to+action
├── TransitionValidator.java                 # 跳转前置校验接口
└── IllegalStateTransitionException.java     # 非法状态跳转异常
```

### 3.2 引擎 API

```java
public class StateMachineEngine<S extends Enum, A extends Enum> {

    // 注册跳转规则
    public void register(S from, A action, S to, TransitionValidator validator);

    // 执行状态跳转（含校验）
    public S transition(S current, A action, TransitionContext context);
}
```

### 3.3 跳转流程

```
transition(current, action, context)
    │
    ├── 1. 查找注册的跳转规则 (from + action → to + validator)
    │       └── 未找到 → 抛 IllegalStateTransitionException
    │
    ├── 2. 执行前置校验 validator.validate(context)
    │       └── 校验失败 → 抛对应 BizException
    │
    └── 3. 返回下一状态 to
            └── Service 层 update 实体 status
```

### 3.4 设计特点

- **泛型设计**：`StateMachineEngine<S, A>` 支持任意状态枚举和操作枚举
- **注册式**：启动时注册所有跳转规则，运行时查找
- **校验解耦**：每个跳转可绑定独立的 `TransitionValidator`
- **异常明确**：非法跳转抛 `IllegalStateTransitionException`，业务校验失败抛对应 `BizException`

              TERMINATED ◄──terminate── BIDDING ◄──startBidding──
                                            │
                                            ▼
                                       EVALUATING
                                            │

## 六、自动流转（定时任务驱动）

> [!important] 规范要求
> SM-R06：系统自动流转由定时任务驱动，**禁止在查询中触发**。即不能在查询接口里顺便改状态，必须由独立定时任务处理。

### 6.1 自动流转任务清单

| 任务名 | 所属模块 | 触发频率 | 职责 | 对应状态机 |
|--------|---------|---------|------|-----------|
| ProjectStatusScheduler | ruoyi-bid | 每小时 | TERMINATED 满 30 天 → ARCHIVED | ProjectStatus |
| NoticeEndScheduler | ruoyi-bid | 每 10 分钟 | PUBLISHED 公告公示期结束 → ENDED | NoticeStatus |
| AwardConfirmScheduler | ruoyi-bid | 每 30 分钟 | PUBLISHED 中标公示期结束无异议 → CONFIRMED | AwardStatus |
| QualificationExpireScheduler | ruoyi-bid | 每天 0 点 | APPROVED 有效期到期 → EXPIRED | QualificationStatus |
| DepositAutoRefundScheduler | ruoyi-bid | 每天 0 点 | 未中标保证金自动退还（BR102） | DepositStatus |
| ConversationIdleScheduler | ruoyi-ai | 每 30 分钟 | ACTIVE 30 分钟无消息 → IDLE；IDLE 7 天 → ARCHIVED | ConversationStatus |
| MemoryDecayScheduler | ruoyi-ai | 每天凌晨 | importance < 阈值的长期记忆自动清理 | — |
| EmbeddingJobScheduler | ruoyi-rag | 每 1 分钟 | 轮询 pgi_ai_embedding_job 执行向量化 | KnowledgeDocStatus |

### 6.2 实现规范

- 使用 `@Scheduled` 注解（简单任务）或接入 `ruoyi-quartz`（需动态配置的任务）
- 定时任务异常捕获并记录日志，不影响下次执行
- 任务执行前加分布式锁（Redisson），防止集群环境重复执行

## 七、状态机使用示例

### 7.1 注册跳转规则

```java
@Configuration
public class StateMachineConfig {

    @Bean
    public StateMachineEngine<ProjectStatus, ProjectAction> projectStateMachine() {
        StateMachineEngine<ProjectStatus, ProjectAction> engine = new StateMachineEngine<>();

        // 注册：项目从 DRAFT 通过 SUBMIT 操作跳到 REGISTERED
        engine.register(ProjectStatus.DRAFT, ProjectAction.SUBMIT,
                        ProjectStatus.REGISTERED, new ProjectSubmitValidator());

        // 注册：项目从 BIDDING 通过 OPEN_BID 操作跳到 EVALUATING
        engine.register(ProjectStatus.BIDDING, ProjectAction.OPEN_BID,
                        ProjectStatus.EVALUATING, new ProjectOpenBidValidator());

        // 注册：任意状态通过 TERMINATE 操作跳到 TERMINATED
        for (ProjectStatus s : ProjectStatus.values()) {
            if (s != ProjectStatus.ARCHIVED) {
                engine.register(s, ProjectAction.TERMINATE,
                                ProjectStatus.TERMINATED, new ProjectTerminateValidator());
            }
        }

        return engine;
    }
}
```

### 7.2 执行状态跳转

```java
@Service
public class ProjectServiceImpl implements IProjectService {

    @Autowired
    private StateMachineEngine<ProjectStatus, ProjectAction> projectStateMachine;

    @Transactional
    public void submit(Long projectId) {
        Project project = projectMapper.selectById(projectId);

        // 执行状态跳转（含校验）
        ProjectStatus next = projectStateMachine.transition(
            project.getStatus(),
            ProjectAction.SUBMIT,
            TransitionContext.of(project)
        );

        project.setStatus(next);
        project.setUpdateBy(SecurityUtils.getUsername());
        project.setUpdateTime(new Date());

        // 更新（含乐观锁）
        int rows = projectMapper.updateById(project);
        if (rows == 0) {
            throw new OptimisticLockException("项目已被其他人修改，请刷新后重试");
        }
    }
}
```

### 7.3 前置校验器示例

```java
public class ProjectOpenBidValidator implements TransitionValidator<ProjectStatus> {

    @Autowired
    private IBidService bidService;

    @Override
    public void validate(TransitionContext context) {
        Project project = context.get("project");
        int bidCount = bidService.countByProjectId(project.getId());

        // BR008：开标需≥3 家投标
        if (bidCount < 3) {
            throw new ProjectStatusException(
                "BIZ-008", "投标不足 3 家，不可开标（当前 " + bidCount + " 家）");
        }
    }
}
```

## 八、状态机与业务规则的协作

状态机负责"能不能跳"，业务规则负责"跳的条件满不满足"：

```
用户操作
    │
    ▼
Service 调用 engine.transition(current, action, context)
    │
    ├── 1. 状态机查找跳转规则（from + action → to）
    │       └── 未找到 → IllegalStateTransitionException（状态不匹配）
    │
    ├── 2. 执行 TransitionValidator（业务规则校验）
    │       └── 校验失败 → BizException（如 BR008 投标不足 3 家）
    │
    └── 3. 返回下一状态 to
            └── Service 层 update status
```

详见 [[业务规则体系]]。

## 九、状态机设计原则

1. **单一职责**：每个状态机只管一个实体的状态
2. **禁止直接 update**：必须经过 `StateMachineEngine.transition()`
3. **校验前置**：跳转前必须校验业务规则
4. **自动流转独立**：定时任务驱动，禁止在查询中触发
5. **异常明确**：非法跳转和业务校验失败抛不同异常
6. **集群安全**：定时任务加分布式锁
