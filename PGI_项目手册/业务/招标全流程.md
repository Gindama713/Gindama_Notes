# 招标全流程

本文档详细阐述 PGI 系统覆盖的招标全生命周期，每个阶段的操作、状态流转、角色、业务规则和辅助模块。适合业务人员、产品经理和客户理解"招标从头到尾怎么走"。

## 一、全流程总览

```
项目立项 ──► 发布公告 ──► 投标 ──► 评标 ──► 中标 ──► 归档
  DRAFT      UNDER_REVIEW   DRAFT    PENDING    DRAFT     ARCHIVED
   │            │             │         │         │
   ▼            ▼             ▼         ▼         ▼
 REGISTERED   PUBLISHED    SUBMITTED  IN_PROGRESS  PUBLISHED
   │            │             │         │         │
   ▼            ▼             ▼         ▼         ▼
 NOTICED       ENDED        OPENED    COMPLETED  CONFIRMED
   │                          │
   ▼                          ▼
 BIDDING                    EVALUATED
   │                          │
   ▼                          ▼
 EVALUATING                  WIN/LOSE
   │
   ▼
 AWARDED
```

## 二、各阶段详解

### 阶段 1：项目立项（代理机构主导）

项目立项是招标流程的起点，由代理机构创建项目并提交注册。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 创建项目 | — | 代理机构 | BR001 项目编号唯一 |
| 修改项目 | — | 代理机构 | BR003 仅 DRAFT 可编辑 |
| 提交注册 | DRAFT→REGISTERED | 代理机构 | BR004 预算>0、BR005 截止时间需 24h 后 |
| 终止项目 | *→TERMINATED | 招标人 | BR015 仅特定状态可终止 |

#### 必填字段

- 项目编号（唯一）
- 项目名称
- 预算金额（>0）
- 投标截止时间（需 24h 后）
- 所属部门（自动填充，多租户隔离）
- 项目类型
- 项目描述
- 附件（招标需求文档）

#### 典型场景

代理机构接到招标人委托，登录系统创建项目，填写项目基本信息和预算，上传招标需求文档，确认无误后提交注册。项目状态从 DRAFT 变为 REGISTERED，进入下一阶段。

### 阶段 2：发布公告（代理机构 + 审核人员）

项目注册后，代理机构创建招标公告并提交审核。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 创建公告 | — | 代理机构 | BR016 公告关联项目 |
| 修改公告 | — | 代理机构 | BR017 仅 DRAFT 可编辑 |
| 提交审核 | DRAFT→UNDER_REVIEW | 代理机构 | BR018 公告内容完整、附件齐全 |
| 审核通过 | UNDER_REVIEW→PUBLISHED | 审核人员 | BR020 公示期≥3 天 |
| 审核驳回 | UNDER_REVIEW→DRAFT | 审核人员 | BR021 驳回需填意见 |
| 撤回公告 | PUBLISHED→WITHDRAWN | 代理机构 | BR028 已发布可撤回 |
| 公示期结束 | PUBLISHED→ENDED | 系统自动 | 定时任务 NoticeEndScheduler |

#### 关键规则

- **BR020 公示期≥3 天**：公告发布时必须设置≥3 天的公示期
- **BR021 驳回需填意见**：审核驳回必须填写驳回原因
- **BR094 不可自审**：审核人员不能审核自己提交的公告

#### 典型场景

代理机构创建招标公告，填写公告内容（项目概况、资格要求、投标截止时间等），提交审核。审核人员查看公告内容，确认无误后审核通过，公告状态变为 PUBLISHED，对外可见。公示期结束后，系统自动将状态变为 ENDED。

### 阶段 3：投标（投标方主导）

公告发布后，符合条件的投标方可以投标。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 我要投标 | — | 投标方 | BR029 同项目仅投一次 |
| 缴纳保证金 | — | 投标方 | BR035 投标前需缴保证金 |
| 上传投标文件 | — | 投标方 | BR082 文件≤100MB |
| 提交投标 | DRAFT→SUBMITTED | 投标方 | BR033 报价≤预算、BR031 截止前提交 |
| 撤回投标 | DRAFT→WITHDRAWN | 投标方 | BR030 仅 DRAFT 可撤回 |
| 开标 | SUBMITTED→OPENED | 系统自动 | BR008 需≥3 家投标 |

#### 关键规则

- **BR029 同项目仅投一次**：同一投标方对同一项目只能投一次标
- **BR033 报价≤预算**：投标报价不能超过项目预算
- **BR031 截止前提交**：投标必须在截止时间前提交
- **BR035 需缴保证金**：投标前必须缴纳保证金
- **BR041 资质已审核**：投标方资质必须已审核通过

#### 典型场景

投标方看到公告后，点击"我要投标"，填写投标信息（报价、投标文件等）。系统校验：同项目是否已投过、保证金是否已缴、资质是否已审核、报价是否超预算。校验通过后提交，投标状态变为 SUBMITTED。投标截止时间到后，系统自动开标，状态变为 OPENED。

### 阶段 4：评标（评标专家 + 评标组长）

开标后，代理机构启动评标，评标专家打分，评标组长完成评标。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 启动评标 | PENDING→IN_PROGRESS | 代理机构 | BR046 专家≥3 人且奇数、所有投标已 OPENED |
| 专家打分 | — | 评标专家 | BR050 打分 0-100、BR051 每人仅打一次 |
| 完成评标 | IN_PROGRESS→COMPLETED | 评标组长 | BR056 所有专家打分完成 |
| 中止评标 | IN_PROGRESS→ABORTED | 代理机构 | BR058 记录中止原因 |
| 评标结果同步 | OPENED→EVALUATED | 系统自动 | 投标状态自动流转 |

#### 关键规则

- **BR046 专家≥3 人且为奇数**：评标专家不少于 3 人且为奇数
- **BR050 打分 0-100**：评标打分必须在 0-100 之间
- **BR051 每人仅打一次**：每个专家对每个投标只能打一次分
- **BR056 所有专家打分完成**：评标组长完成评标前，所有专家必须打分完成

#### 典型场景

代理机构分配评标专家（≥3 人且为奇数），启动评标。评标专家查看分配给自己的投标文件，独立打分（0-100 分）。所有专家打分完成后，评标组长点击"完成评标"，系统汇总得分，评标状态变为 COMPLETED，投标状态自动变为 EVALUATED。

### 阶段 5：中标（代理机构 + 招标人）

评标完成后，代理机构发布中标公示，公示期结束后确认中标。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 发布中标公示 | DRAFT→PUBLISHED | 代理机构 | BR059 评标已完成、BR061 中标金额=投标报价 |
| 公示期结束 | PUBLISHED→CONFIRMED | 系统自动 | 定时任务 AwardConfirmScheduler |
| 取消中标 | PUBLISHED→CANCELED | 招标人 | BR070 记录取消原因 |

#### 关键规则

- **BR059 评标已完成**：发布中标公示前，评标必须已完成
- **BR061 中标金额=投标报价**：中标金额必须等于中标人的投标报价
- **BR063 公示期≥3 天**：中标公示期不少于 3 天
- **BR064 一项目一有效中标**：一个项目只能有一个有效中标

#### 典型场景

评标完成后，代理机构根据得分确定中标候选人，发布中标公示（含中标人、中标金额、公示期）。公示期结束无异议，系统自动确认中标，状态变为 CONFIRMED。如有异议，招标人可取消中标，状态变为 CANCELED。

### 阶段 6：归档（系统自动）

中标确认后，项目进入归档阶段。

#### 操作清单

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 项目归档 | AWARDED→ARCHIVED | 系统自动 | 定时任务 ProjectStatusScheduler |

#### 典型场景

中标确认后 30 天，系统自动将项目状态变为 ARCHIVED，项目进入只读状态，不可再修改。归档后的项目可随时查询，作为历史记录。

## 三、贯穿全流程的辅助模块

### 3.1 附件管理（M09）

- 全流程各环节上传文件（招标文件、投标文件、资质证书等）
- MD5 去重、类型白名单、逻辑删除
- `biz_type + biz_id` 多态关联不同业务

| biz_type | 关联业务 |
|----------|---------|
| project | 项目附件 |
| notice | 公告附件 |
| document | 招标文件 |
| bid | 投标文件 |
| qualification | 资质证书 |

### 3.2 审核管理（M10）

- 公告审核、资质审核、文件备案审核
- 不可删除、不可自审、驳回需填意见
- 审核记录永久保留（3 年追溯）

### 3.3 保证金管理（M11）

保证金贯穿投标到中标的全流程：

```
投标前缴纳 → 中标后转履约 → 未中标自动退还 → 违规没收
PENDING     → PAID          → REFUNDED          → FORFEITED
```

| 操作 | 状态流转 | 角色 | 关键规则 |
|------|---------|------|---------|
| 缴纳 | PENDING→PAID | 投标方 | BR098 金额>0 |
| 退还 | PAID→REFUNDED | 代理机构/系统自动 | BR103 未中标方 |
| 没收 | PAID→FORFEITED | 代理机构 | BR104 违规方 |

### 3.4 场地预约（M12）

- 开标场地预约（时间冲突校验）
- 代理机构预约/变更/取消
- BR105 时间冲突校验、BR110 结束>开始

### 3.5 消息通知（M15）

- 各环节状态变更自动通知相关角色
- 站内信 + 邮件（事件驱动）
- 通知场景：公告发布、投标截止、评标完成、中标公示、保证金退还等

## 四、状态流转全景

```
项目:  DRAFT → REGISTERED → NOTICED → BIDDING → EVALUATING → AWARDED → ARCHIVED
                                                                  ↓
                                                              TERMINATED

公告:  DRAFT → UNDER_REVIEW → PUBLISHED → ENDED
                              ↓
                          WITHDRAWN

投标:  DRAFT → SUBMITTED → OPENED → EVALUATED → WIN/LOSE
          ↓
      WITHDRAWN

评标:  PENDING → IN_PROGRESS → COMPLETED
                    ↓
                ABORTED

中标:  DRAFT → PUBLISHED → CONFIRMED
                    ↓
                CANCELED

资质:  DRAFT → SUBMITTED → APPROVED → EXPIRED
                    ↓
                REJECTED

保证金: PENDING → PAID → REFUNDED / FORFEITED
```

## 六、业务流程与角色的对应

| 阶段 | 主导角色 | 协作角色 | 系统自动 |
|------|---------|---------|---------|
| 项目立项 | 代理机构 | 招标人（确认） | — |
| 发布公告 | 代理机构 | 审核人员（审核） | 公示期结束→ENDED |
| 投标 | 投标方 | — | 截止时间到→开标 |
| 评标 | 评标专家 + 评标组长 | 代理机构（启动/中止） | 评标结果同步 |
| 中标 | 代理机构 | 招标人（确认/取消） | 公示期结束→CONFIRMED |
| 归档 | — | — | 30 天后→ARCHIVED |
| 保证金 | 投标方（缴纳） | 代理机构（退还/没收） | 未中标自动退还 |
| 资质 | 投标方 | 审核人员 | 有效期到期→EXPIRED |

详见 [[03-角色分配]]。

## 七、异常场景处理

| 异常场景 | 处理方式 |
|---------|---------|
| 投标不足 3 家 | BR008 阻止开标，代理机构可终止项目 |
| 评标专家不足 | BR046 阻止启动评标，代理机构补充专家 |
| 公告审核驳回 | 状态回退到 DRAFT，代理机构修改后重新提交 |
| 中标有异议 | 招标人取消中标，状态变为 CANCELED |
| 保证金未缴 | BR035 阻止投标提交 |
| 资质过期 | 系统自动 EXPIRED，投标方续期后重新提交 |
