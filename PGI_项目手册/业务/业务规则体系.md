# 业务规则体系

本文档完整列出 PGI 系统的 120 条编号化业务规则、校验机制、典型规则详解、6 种幂等方案和 SSOT 强制约束。适合开发人员理解"每条规则是什么、怎么校验、违反怎么办"。

## 一、为什么需要编号化业务规则

### 1.1 传统规则管理的问题

| 问题 | 后果 |
|------|------|
| 规则散落在代码各处 | 改一个规则要找半天 |
| 规则靠人记 | 新人不知道有哪些规则，容易漏校验 |
| 规则无版本 | 规则变更后无法追溯 |
| 规则与文档脱节 | 文档说 A，代码写 B |

### 1.2 编号化规则的优势

- **可追溯**：每条规则有唯一编号（BR001-BR120）
- **可检索**：通过编号快速定位规则定义和代码实现
- **可校验**：规则直接映射代码校验逻辑
- **SSOT**：规则在开发规范中定义，文档与代码一致

## 三、规则校验机制

### 3.1 校验流程

```
Controller 接收请求
    │
    ▼
Service 调用业务方法
    │
    ├── 1. RuleValidator.validate(context)  ← 业务规则校验
    │       └── 失败 → 抛 BizException (errorCode)
    │
    ├── 2. StateMachineEngine.transition()  ← 状态机校验
    │       └── 失败 → 抛 IllegalStateTransitionException
    │
    └── 3. Mapper 执行数据库操作
            └── 乐观锁失败 → 抛 OptimisticLockException
```

### 3.2 规则校验器清单

每类规则对应一个 `Validator`，位于 `ruoyi-bid/rule/` 包下：

| 校验器 | 规则范围 | 数量 |
|--------|---------|------|
| `ProjectRuleValidator` | BR001-BR015 | 15 |
| `NoticeRuleValidator` | BR016-BR028 | 13 |
| `BidRuleValidator` | BR029-BR045 | 17 |
| `EvaluationRuleValidator` | BR046-BR058 | 13 |
| `AwardRuleValidator` | BR059-BR070 | 12 |
| `QualificationRuleValidator` | BR071-BR080 | 10 |
| `AttachmentRuleValidator` | BR081-BR088 | 8 |
| `AuditRuleValidator` | BR089-BR096 | 8 |
| `DepositRuleValidator` | BR097-BR104 | 8 |
| `VenueRuleValidator` | BR105-BR110 | 6 |

### 3.3 校验器实现示例

```java
@Component
public class ProjectRuleValidator {

    @Autowired
    private IProjectService projectService;

    @Autowired
    private IBidService bidService;

    /**
     * BR001: 项目编号唯一
     */
    public void validateProjectCodeUnique(Project project) {
        Project existing = projectService.getByCode(project.getProjectCode());
        if (existing != null && !existing.getId().equals(project.getId())) {
            throw new BizException("BIZ-001", "项目编号已存在: " + project.getProjectCode());
        }
    }

    /**
     * BR004: 预算必须大于 0
     */
    public void validateBudgetPositive(BigDecimal budget) {
        if (budget == null || budget.compareTo(BigDecimal.ZERO) <= 0) {
            throw new BizException("BIZ-004", "项目预算必须大于 0");
        }
    }

    /**
     * BR005: 投标截止时间需在 24 小时后
     */
    public void validateDeadlineAfter24h(Date deadline) {
        Date now = new Date();
        long diff = deadline.getTime() - now.getTime();
        if (diff < 24 * 60 * 60 * 1000L) {
            throw new BizException("BIZ-005", "投标截止时间需在 24 小时后");
        }
    }

    /**
     * BR008: 开标需≥3 家投标
     */
    public void validateBidCountForOpenBid(Long projectId) {
        int bidCount = bidService.countByProjectId(projectId);
        if (bidCount < 3) {
            throw new ProjectStatusException(
                "BIZ-008", "投标不足 3 家，不可开标（当前 " + bidCount + " 家）");
        }
    }
}
```

## 四、典型规则详解

### 4.1 BR008：开标需≥3 家投标

| 维度 | 说明 |
|------|------|
| 规则内容 | 项目开标时，投标数量必须≥3 家 |
| 校验时机 | 项目状态从 BIDDING → EVALUATING（openBid 操作） |
| 校验器 | ProjectRuleValidator.validateBidCountForOpenBid |
| 违反异常 | ProjectStatusException("BIZ-008", "投标不足 3 家，不可开标") |
| 关联模块 | ruoyi-bid |

```java
if (bidCount < 3) {
    throw new ProjectStatusException(
        "BIZ-008", "投标不足 3 家，不可开标（当前 " + bidCount + " 家）");
}
```

### 4.2 BR033：报价不能超过预算

| 维度 | 说明 |
|------|------|
| 规则内容 | 投标报价不能超过项目预算 |
| 校验时机 | 投标提交时（DRAFT → SUBMITTED） |
| 校验器 | BidRuleValidator |
| 违反异常 | BizException("BIZ-033", "投标报价不能超过项目预算") |

```java
if (bid.getAmount().compareTo(project.getBudget()) > 0) {
    throw new BizException("BIZ-033", "投标报价不能超过项目预算");
}
```

## 五、规则与状态机的协作

业务规则校验通过后，才执行状态跳转：

```
用户操作（如"提交投标"）
    │
    ▼
BidService.submit(bidId)
    │
    ├── 1. BidRuleValidator 校验业务规则
    │       ├── BR033: 报价≤预算？
    │       ├── BR031: 截止前提交？
    │       ├── BR035: 保证金已缴纳？
    │       └── BR041: 资质已审核？
    │       └── 任一失败 → 抛 BizException
    │
    ├── 2. StateMachineEngine.transition(DRAFT, SUBMIT, context)
    │       └── 状态机校验通过 → 返回 SUBMITTED
    │
    └── 3. bidMapper.update status = SUBMITTED
```

详见 [[状态机设计]]。

## 六、6 种幂等方案

> [!important] 规范要求
> AC-07：所有写操作必须实现幂等性。违反后果：数据重复。

### 6.1 幂等方案清单

| 方案 | 适用场景 | 实现方式 | 示例 |
|------|---------|---------|------|
| **requestId** | 前端每次请求带唯一 requestId | 后端 Redis SETNX 去重 | 表单提交 |
| **MD5 去重** | 文件上传 | 附件 MD5 一致则复用 | 附件上传（BR085） |
| **防重 Token** | 表单提交 | 提交前申请 Token，提交时校验销毁 | 投标提交 |
| **状态机** | 状态流转 | DRAFT→SUBMITTED 只能一次 | 项目提交 |
| **唯一索引** | 项目编号、证书编号 | 数据库层防重 | BR001 项目编号唯一 |
| **分布式锁** | 集群并发 | Redisson 锁 | 定时任务执行 |

### 6.2 @Idempotent 注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Idempotent {
    int expireSeconds() default 600;  // 默认 600 秒
}
```

### 6.3 IdempotentAspect 切面

```java
@Aspect
@Component
public class IdempotentAspect {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Around("@annotation(idempotent)")
    public Object around(ProceedingJoinPoint point, Idempotent idempotent) throws Throwable {
        HttpServletRequest request = ServletUtils.getRequest();
        String requestId = request.getHeader("X-Request-Id");

        if (StringUtils.isEmpty(requestId)) {
            return point.proceed();  // 无 requestId 不做幂等
        }

        String key = "idempotent:" + requestId;
        Boolean success = redisTemplate.opsForValue()
            .setIfAbsent(key, "1", idempotent.expireSeconds(), TimeUnit.SECONDS);

        if (Boolean.FALSE.equals(success)) {
            throw new RepeatSubmitException("请勿重复提交");
        }

        return point.proceed();
    }
}
```

### 6.4 幂等使用示例

```java
@RestController
@RequestMapping("/api/bid")
public class BidController {

    @Idempotent(expireSeconds = 600)  // 10 分钟内防重复
    @PreAuthorize("@ss.hasPermi('bid:bid:submit')")
    @PutMapping("/submit/{id}")
    public AjaxResult submit(@PathVariable Long id) {
        bidService.submit(id);
        return AjaxResult.success();
    }
}
```

## 七、异常体系

### 7.1 5 大类异常

系统定义了 5 大类异常，统一继承 `PgiException`，由 `GlobalExceptionHandler` 统一捕获：

| 分类 | 错误码前缀 | HTTP | 重试 | 典型异常 | 数量 |
|------|-----------|------|------|---------|------|
| 业务异常 | BIZ | 400 | 否 | ProjectStatusException, BidDuplicateException | 20 |
| 权限异常 | AUTH | 403 | 否 | UnauthorizedException, ForbiddenException | 5 |
| AI 异常 | AI | 500 | 是(指数退避) | AiModelTimeoutException, AiVectorStoreException | 11 |
| 系统异常 | SYS | 500 | 否 | OptimisticLockException, DeadlockException | 6 |
| 外部异常 | EXT | 502 | 是(固定间隔) | EmailSendException, SmsSendException | 5 |
| **合计** | — | — | — | — | **53** |

### 7.2 异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(PgiException.class)
    public AjaxResult handlePgiException(PgiException e) {
        log.error("PGI异常: code={}, msg={}", e.getErrorCode(), e.getMessage(), e);
        AjaxResult result = new AjaxResult();
        result.put(AjaxResult.CODE_TAG, e.getErrorCode());
        result.put(AjaxResult.MSG_TAG, e.getErrorMessage());
        return result;
    }

    @ExceptionHandler(IllegalStateTransitionException.class)
    public AjaxResult handleStateTransition(IllegalStateTransitionException e) {
        log.error("状态跳转异常: {}", e.getMessage());
        return AjaxResult.error("非法状态跳转: " + e.getMessage());
    }
}
```

## 八、SSOT 强制约束

### 8.1 8 条 AI 执行约束

| 约束编号 | 约束内容 | 违反后果 |
|---------|---------|---------|
| AC-01 | AI 生成代码前必须完整阅读本文档相关章节 | 代码不予合并 |
| AC-02 | 禁止修改数据库表结构、新增自定义字段 | 代码回滚 |
| AC-03 | 禁止修改接口 URL、请求/响应结构 | 接口测试失败 |
| AC-04 | 禁止修改状态定义与状态流转规则 | 业务逻辑错误 |
| AC-05 | 禁止违反业务规则表中的任何规则 | 业务异常 |
| AC-06 | 禁止跨模块直接操作其他模块数据库表 | 架构违规 |
| AC-07 | 所有写操作必须实现幂等性 | 数据重复 |
| AC-08 | 所有异常必须按第六章分类抛出 | 异常处理混乱 |

### 8.2 缺口错误码策略

规范第五章接口表"可能错误码"中约 30 个错误码未定义独立异常类，**复用相近语义异常类** + 构造器动态覆盖文案。例如开标不足 3 家 → `throw new ProjectStatusException("投标不足 3 家，不可开标")`。

## 九、规则维护原则

1. **SSOT**：规则在开发规范中定义，文档与代码冲突时以文档为准
2. **编号唯一**：每条规则有唯一编号，不可复用
3. **校验前置**：规则在 Service 层校验，不依赖前端
4. **异常明确**：违反规则抛对应 BizException，含 errorCode
5. **可追溯**：规则变更需更新文档，保留版本历史
