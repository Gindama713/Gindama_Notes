# 亮点展示

本文档系统阐述 PGI 项目的核心亮点、技术优势、与传统招标系统的对比、适用场景和商业价值。适合销售售前、潜在买家、决策者快速理解项目价值。

## 一、项目定位

PGI 系统不是又一个招标系统，而是 **AI Native 的招标全流程管理平台**。它的核心差异在于：让 AI 真正"动手"操作业务（不是只会聊天），同时用状态机 + 规则引擎 + 幂等机制 + 审计回滚把安全做到法规级。

**一句话总结**：让招标业务既**规范严谨**（状态机+规则+幂等+审计），又**智能高效**（AI 对话+RAG+工具调用），并且让企业**敢用 AI**（写操作确认+快照回滚）。

## 二、五大核心亮点

### 亮点 1：AI 真正能"动手"（不是只会聊天）

这是项目区别于市面所有招标系统的**本质差异**。

#### 传统 AI 招标方案 vs 本系统

| 维度 | 传统 AI 招标方案 | PGI 系统 |
|------|----------------|---------|
| AI 能力 | 只能聊天，业务仍需手动点击菜单 | AI 通过 Function Calling 真正调用业务工具 |
| 交互方式 | 用户问 → AI 答 | 用户说 → AI 做 → 确认 → 完成 |
| 业务闭环 | 无 | 12 个工具覆盖招标全流程 |

#### 12 个工具覆盖招标全流程

| 工具类别 | 工具 | 功能 | 读写 |
|---------|------|------|------|
| 招标类 | SearchProjectTool | 搜索招标项目 | 只读 |
| 招标类 | GetProjectDetailTool | 获取项目详情 | 只读 |
| 招标类 | AddProgressTool | 添加项目进度 | 写（需确认） |
| 招标类 | UploadDocumentTool | 上传投标文件 | 写（需确认） |
| 招标类 | CheckQualificationTool | 查询资质状态 | 只读 |
| 招标类 | SubmitQualificationTool | 提交资质审核 | 写（需确认） |
| 资讯类 | SearchNewsTool | 搜索资讯 | 只读 |
| 资讯类 | GetNewsDetailTool | 获取资讯详情 | 只读 |
| 资讯类 | UpdateSubscriptionTool | 更新订阅 | 写（需确认） |
| 系统类 | GetUserProfileTool | 获取用户画像 | 只读 |
| 系统类 | SendNotificationTool | 发送通知 | 写（需确认） |
| RAG 类 | SearchRagDocTool | 检索知识库文档片段 | 只读 |

#### 典型场景演示

用户说一句"帮我把 PGI-2026-001 项目进度更新为评标中"，AI 就能完成操作：

1. AI 识别意图，调用 `AddProgressTool`
2. 检测到写操作，创建 `pgi_ai_action_record`，弹窗确认
3. 用户确认后执行，记录 before/after 快照
4. 返回"已更新项目进度为评标中"
5. 用户可随时回滚该操作

详见 [[工具调用体系]] 和 [[AI智能体]]。

### 亮点 2：RAG 知识库让 AI"懂企业"

#### 传统聊天机器人 vs 本系统

| 维度 | 传统聊天机器人 | PGI 系统 |
|------|---------------|---------|
| 知识来源 | 模型训练数据 | 企业自有文档 |
| 回答准确性 | 泛泛而谈 | 有据可查 |
| 可更新性 | 需重新训练 | 上传文档即可 |
| 幻觉风险 | 高 | 低（有上下文约束） |

#### 完整 RAG 流程

```
文档上传 → Tika 解析(PDF/Word/MD/TXT)
    → 分块(500字, 重叠50)
    → Embedding 批量向量化(批20)
    → ChromaDB 存储
    → 检索 Top-K(5)
    → QuestionAnswerAdvisor 注入上下文
    → DeepSeek 生成回答
```

#### 支持的文档类型

| 格式 | 解析工具 | 场景 |
|------|---------|------|
| PDF | Apache Tika | 招标法规、企业制度 |
| Word | Apache Tika | 历史标书、评标报告 |
| Markdown | Apache Tika | 内部文档 |
| TXT | Apache Tika | 纯文本资料 |

#### 商业价值

- 招标法规、企业制度上传后，AI 对话即可精准引用
- 历史标书积累成知识库，新人快速复用
- 文档更新后无需重新训练，上传即生效
- AI 回答有据可查，降低幻觉风险

详见 [[RAG知识库]]。

### 亮点 3：9 状态机 + 120 规则，流程严谨到法规级

#### 传统系统 vs 本系统

| 维度 | 传统系统 | PGI 系统 |
|------|---------|---------|
| 状态管理 | 状态字段被人工随意改 | 状态机引擎统一校验 |
| 业务规则 | 靠人记、易漏 | 120 条规则代码强制执行 |
| 合规性 | 难以保证 | 法规级硬约束 |

#### 9 个状态机覆盖全部业务实体

| 实体 | 状态流转 |
|------|---------|
| 项目 | DRAFT→REGISTERED→NOTICED→BIDDING→EVALUATING→AWARDED→ARCHIVED |
| 投标 | DRAFT→SUBMITTED→OPENED→EVALUATED→WIN/LOSE |
| 公告 | DRAFT→UNDER_REVIEW→PUBLISHED→ENDED |
| 招标文件 | DRAFT→SUBMITTED→APPROVED→PUBLISHED→ARCHIVED |
| 评标 | PENDING→IN_PROGRESS→COMPLETED |
| 中标 | DRAFT→PUBLISHED→CONFIRMED |
| 资质 | DRAFT→SUBMITTED→APPROVED→EXPIRED |
| 知识库文档 | UPLOADED→PROCESSING→READY |
| AI 会话 | ACTIVE→IDLE→ARCHIVED |

#### 120 条业务规则示例

| 规则编号 | 内容 | 类别 |
|---------|------|------|
| BR008 | 开标需≥3 家投标 | 项目 |
| BR020 | 公告公示期≥3 天 | 公告 |
| BR033 | 投标报价≤预算 | 投标 |
| BR046 | 评标专家≥3 人且为奇数 | 评标 |
| BR061 | 中标金额=投标报价 | 中标 |
| BR072 | 证书编号唯一 | 资质 |
| BR102 | 未中标保证金自动退还 | 保证金 |

非法操作直接抛异常，杜绝人工越权改状态。详见 [[状态机设计]] 和 [[业务规则体系]]。

### 亮点 4：AI 操作可审计、可回滚

> 业界难题：AI 直接改业务数据，出错没法追溯——这是企业不敢用 AI 的核心顾虑。

#### 四重安全机制

| 机制 | 说明 | 实现表 |
|------|------|--------|
| 写操作确认 | AI 执行写操作前弹窗，用户确认后才执行 | pgi_ai_action_record |
| before/after 快照 | 记录操作前后的数据快照 | pgi_ai_action_record |
| 一键回滚 | 用户可对已执行的操作调用回滚 | pgi_ai_action_record |
| 全量日志 | 工具调用日志 + AI 操作记录 + 用量日志 | pgi_ai_tool_call_log / pgi_ai_usage_log |

#### 完整审计链

```
用户指令 → AI 识别 → 创建 action_record(confirm_status='0')
    → 用户确认 → 执行工具(记录 before/after)
    → 完成 → 记录 tool_call_log
    → 用户可回滚(基于 before 快照)
    → 用量日志记录 token 消耗
```

#### 商业价值

- **让企业敢用 AI**：出了错能追溯、能恢复
- **满足合规审计**：AI 的每一次"动手"都有据可查
- **责任清晰**：操作前需用户确认，AI 不会擅自改数据

详见 [[工具调用体系]]。

### 亮点 5：全链路工程化，企业级可靠

#### 6 种幂等方案

| 方案 | 适用场景 |
|------|---------|
| requestId | 前端每次请求带唯一 requestId |
| MD5 去重 | 文件上传 |
| 防重 Token | 表单提交 |
| 状态机 | 状态流转天然防重 |
| 唯一索引 | 项目编号、证书编号 |
| 分布式锁 | 集群并发 |

#### 其他工程化能力

| 维度 | 方案 |
|------|------|
| 并发控制 | 乐观锁 version 字段 |
| 多租户隔离 | dept_id + @DataScope AOP |
| 事件驱动解耦 | ApplicationEvent 解决循环依赖 |
| SSOT 规范 | 文档为唯一事实来源 |
| 定时任务自动流转 | 公示期结束/保证金退还/资质过期全自动 |
| 集群定时任务 | Redisson 分布式锁防重复执行 |

## 五、适用场景

### 场景 1：大型企业招标管理

- 多部门/多子公司，需要数据隔离
- 招标项目多，AI 辅助查询和操作提效
- 法规严格，需要状态机 + 规则引擎保证合规
- 知识库积累企业招标制度，AI 辅助合规判断

### 场景 2：招标代理机构

- 同时代理多个项目，AI 对话快速查询进展
- 知识库积累历史标书和法规，AI 辅助报价决策
- 操作可审计，满足客户对代理机构的合规要求
- 多租户隔离，不同客户项目互不可见

### 场景 3：政府采购平台

- 公示期、专家数等法规级硬约束
- 全流程可追溯（审核记录 3 年保留）
- AI 辅助撰写公告/报告
- 多部门协作，权限分明

### 场景 4：招投标交易平台

- AI 降低用户使用门槛（自然语言交互）
- RAG 知识库提供智能问答服务
- 用量审计支撑按量计费商业模式
- Docker 部署支持快速扩容

## 六、商业价值量化
