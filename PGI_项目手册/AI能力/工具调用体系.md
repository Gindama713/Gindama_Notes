# 工具调用体系

本文档详细阐述 PGI 系统 AI 工具调用体系的原理、12 个工具清单、工具实现、注册机制、调用日志、写操作确认与回滚、权限校验。适合开发人员理解"AI 怎么调用工具、怎么保证安全"。

## 一、工具调用原理

```
用户："帮我查一下 XX 项目进展"
        │
        ▼
DeepSeek 大模型识别意图
        │
        ▼
返回 tool_call: { name: "searchProject", args: {"keyword":"XX"} }
        │
        ▼
Spring AI 自动调用 SearchProjectTool.execute(args)
        │
        ▼
工具内部调用 IProjectService 查询业务数据
        │
        ▼
结果返回大模型
        │
        ▼
大模型基于结果生成自然语言回复
```

### 1.1 Function Calling 机制

Spring AI 2.0 通过 `@Tool` 注解自动注册 `ToolCallback`，AI 大模型根据用户意图自动选择调用哪个工具，并传入参数。

### 1.2 工具调用 vs 传统 API 调用

| 维度 | 传统 API 调用 | AI 工具调用 |
|------|-------------|-----------|
| 触发方式 | 前端点击按钮 | 用户自然语言 |
| 参数构造 | 前端表单 | AI 自动从对话提取 |
| 调用方 | 前端代码 | AI 大模型 |
| 灵活性 | 固定流程 | 自然语言灵活 |

## 三、工具实现示例

### 3.1 只读工具示例

```java
@Component
public class SearchProjectTool {

    @Autowired
    private IProjectService projectService;

    @Tool(description = "根据关键词搜索招标项目，返回项目列表。"
                       + "参数: keyword-搜索关键词(项目编号或名称)")
    public List<ProjectVO> searchProject(String keyword) {
        // 权限校验（MB-R04）
        SecurityUtils.checkPermi("bid:project:list");

        List<Project> projects = projectService.searchByKeyword(keyword);
        return projects.stream()
            .map(this::toVO)
            .collect(Collectors.toList());
    }

    private ProjectVO toVO(Project project) {
        ProjectVO vo = new ProjectVO();
        BeanUtils.copyProperties(project, vo);
        return vo;
    }
}
```

### 3.2 写操作工具示例

```java
@Component
public class AddProgressTool {

    @Autowired
    private IProjectService projectService;

    @Autowired
    private IAuditService auditService;

    @Tool(description = "添加项目进度记录。"
                       + "参数: projectId-项目ID, progress-进度描述, "
                       + "status-进度状态(如'评标中')")
    public String addProgress(Long projectId, String progress, String status) {
        // 权限校验
        SecurityUtils.checkPermi("bid:project:edit");

        // 记录操作前快照（用于回滚）
        Project before = projectService.getById(projectId);

        // 执行业务操作
        projectService.addProgress(projectId, progress, status);

        // 记录操作后快照
        Project after = projectService.getById(projectId);

        return String.format("已添加项目 %d 的进度: %s（状态: %s）",
            projectId, progress, status);
    }
}
```

## 四、工具注册机制

### 4.1 ToolRegistry

```
ToolRegistry
  ├── 启动时扫描 @Tool 注解
  ├── 注册为 ToolCallback
  └── ChatClient.tools(callbacks) 绑定
```

```java
@Component
public class ToolRegistry {

    @Autowired
    private List<Object> toolBeans;

    private List<ToolCallback> callbacks;

    @PostConstruct
    public void init() {
        callbacks = new ArrayList<>();
        for (Object bean : toolBeans) {
            // 扫描 @Tool 注解的方法，注册为 ToolCallback
            ToolCallbacks.from(bean).forEach(callbacks::add);
        }
    }

    public List<ToolCallback> getCallbacks() {
        return callbacks;
    }
}
```

### 4.2 ChatClient 绑定工具

```java
@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder,
                                  ToolRegistry toolRegistry) {
        return builder
            .defaultTools(toolRegistry.getCallbacks().toArray())
            .build();
    }
}
```

## 五、工具调用日志

> 每次工具调用都记录到 `pgi_ai_tool_call_log`，可追溯 AI 的每一次"动手"。

### 5.1 日志表

| 字段 | 说明 |
|------|------|
| id | 日志 ID |
| tool_name | 工具名称 |
| input_args | 入参 JSON |
| output_result | 出参 JSON |
| duration_ms | 耗时 |
| status | 成功/失败 |
| conversation_id | 关联会话 |
| user_id | 调用用户 |
| call_time | 调用时间 |
| error_msg | 错误信息 |

### 5.2 ToolCallLogAspect

通过 `@Around("@annotation(@Tool)")` AOP 自动记录：

```java
@Aspect
@Component
public class ToolCallLogAspect {

    @Autowired
    private IAIToolCallLogService toolCallLogService;

    @Around("@annotation(org.springframework.ai.tool.annotation.Tool)")
    public Object logToolCall(ProceedingJoinPoint point) throws Throwable {
        long start = System.currentTimeMillis();
        AIToolCallLog log = new AIToolLog();

        // 记录入参
        log.setToolName(point.getSignature().getName());
        log.setInputArgs(JSON.toJSONString(point.getArgs()));
        log.setUserId(SecurityUtils.getUserId());
        log.setCallTime(new Date());

        Object result;
        try {
            result = point.proceed();
            log.setStatus("SUCCESS");
            log.setOutputResult(JSON.toJSONString(result));
        } catch (Throwable e) {
            log.setStatus("FAILED");
            log.setErrorMsg(e.getMessage());
            throw e;
        } finally {
            log.setDurationMs(System.currentTimeMillis() - start);
            toolCallLogService.insert(log);
        }

        return result;
    }
}
```

## 六、写操作确认与回滚

> [!warning] 安全铁律
> 写操作工具（`risk_level='1'或'2'`）执行前**必须用户确认**，并记录前后快照支持回滚。

### 6.1 风险等级定义

| risk_level | 含义 | need_confirm | 示例 |
|------------|------|-------------|------|
| 0 | 只读 | 否 | SearchProject |
| 1 | 低风险写 | 是 | AddProgress |
| 2 | 高风险写 | 是 | SubmitQualification |

### 6.2 确认流程

```
AI 调用写工具
   │
   ▼
检测 need_confirm='1'
   │
   ▼
创建 pgi_ai_action_record (confirm_status='0')
   │
   ▼
暂停执行，前端弹窗确认
   │
   ├── 用户确认 → 执行工具 → 记录 before/after 快照 → 完成
   │
   └── 用户拒绝 → 取消执行 → 记录拒绝原因
```

### 6.3 ToolConfirmAdvisor

```java
public class ToolConfirmAdvisor implements BaseAdvisor {

    @Autowired
    private IAIActionRecordService actionRecordService;

    @Override
    public ChatResponse adviseCall(ChatClientRequest request, CallChatOptions options) {
        // 检查是否包含写工具调用
        List<ToolCall> toolCalls = options.getToolCalls();
        for (ToolCall tc : toolCalls) {
            AITool tool = toolService.getByBeanName(tc.name());
            if ("1".equals(tool.getNeedConfirm())) {
                // 创建待确认记录
                AIActionRecord record = new AIActionRecord();
                record.setConversationId(request.context().get("conversationId"));
                record.setUserId(SecurityUtils.getUserId());
                record.setToolName(tc.name());
                record.setToolArgs(tc.arguments());
                record.setConfirmStatus("0");
                actionRecordService.insert(record);

                // 暂停执行，返回确认请求
                return ChatResponse.confirmRequired(record.getId());
            }
        }
        return nextAdvisor.adviseCall(request, options);
    }
}
```

### 6.4 回滚机制

```java
@RestController
@RequestMapping("/api/ai/action")
public class AIActionController {

    @PutMapping("/rollback/{id}")
    public AjaxResult rollback(@PathVariable Long id) {
        AIActionRecord record = actionRecordService.getById(id);

        // 校验：必须已执行且未回滚
        if (!"1".equals(record.getConfirmStatus())) {
            return AjaxResult.error("操作未确认，无法回滚");
        }
        if ("1".equals(record.getRollbackStatus())) {
            return AjaxResult.error("操作已回滚");
        }

        // 根据 before_snapshot 恢复数据
        String beforeSnapshot = record.getBeforeSnapshot();
        String toolName = record.getToolName();

        toolRollbackService.rollback(toolName, beforeSnapshot);

        // 更新回滚状态
        record.setRollbackStatus("1");
        actionRecordService.update(record);

        return AjaxResult.success("已回滚");
    }
}
```

| 字段 | 说明 |
|------|------|
| id | 记录 ID |
| conversation_id | 关联会话 |

## 七、权限校验

> [!important] 规范 MB-R04
> AI 模块调用业务模块必须通过 Service 接口 + 权限校验。

### 7.1 权限校验机制

- 工具实现中注入业务 Service
- 执行前校验当前用户权限（`SecurityUtils.checkPermi`）
- AI 不能越权操作（如投标方不能操作招标方数据）

### 7.2 权限校验示例

```java
@Tool(description = "添加项目进度")
public String addProgress(Long projectId, String progress, String status) {
    // 权限校验：当前用户必须有 bid:project:edit 权限
    SecurityUtils.checkPermi("bid:project:edit");

    // 数据权限校验：当前用户能否操作该项目（dept_id 隔离）
    Project project = projectService.getById(projectId);
    if (!dataScopeService.canOperate(project.getDeptId())) {
        throw new ForbiddenException("无权操作该项目");
    }

    return projectService.addProgress(projectId, progress, status);
}
```

## 十、工具扩展指南

### 10.1 新增工具步骤

1. 在 `ruoyi-ai/tool/` 对应子包下创建工具类
2. 方法加 `@Tool` 注解，写清楚 description
3. 注入业务 Service，执行前校验权限
4. 写操作工具需配置 `risk_level` 和 `need_confirm`
5. 在 `pgi_ai_tool` 表注册工具元数据

### 10.2 工具设计原则

- **单一职责**：一个工具只做一件事
- **描述清晰**：`@Tool` 的 description 要让 AI 能准确识别意图
- **参数明确**：参数名和类型清晰，AI 能正确传参
- **权限校验**：执行前必须校验当前用户权限
- **异常处理**：业务异常抛 `BizException`，AI 会基于异常信息回复用户
