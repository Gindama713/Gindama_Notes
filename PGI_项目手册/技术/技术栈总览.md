# 技术栈总览

本文档完整列出 PGI 系统的所有技术选型、版本、选型理由和版本锁定原则。适合开发人员快速了解"用了什么技术、为什么选这个"。

## 一、后端技术栈

### 1.1 核心框架

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| **JDK** | OpenJDK | 21 | LTS 长期支持，支持虚拟线程（提升并发能力）、模式匹配、记录类等新特性 |
| **后端框架** | Spring Boot | 4.0.6 | 主流企业级框架，生态成熟，与 Spring AI 原生集成，支持 JDK 21 |
| **AI 框架** | Spring AI | 2.0.0 | 原生支持 ChatClient / @Tool / Advisor / 向量存储，与 Spring Boot 4.0 深度集成 |
| **安全框架** | Spring Security + JWT | — | 无状态认证，支持多终端（Web/App/小程序），JWT Token 可跨服务传递 |

### 1.2 数据与持久化

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| **ORM** | MyBatis + PageHelper | 4.0.1 | SQL 透明可控，符合招标业务对数据精确性的要求；乐观锁/逻辑删除手动写更清晰 |
| **数据库连接池** | Druid | 1.2.28 | 高性能 + 内置 SQL 监控面板，可分析慢 SQL |
| **业务数据库** | MySQL | 8.4 | 主流关系型数据库，支持窗口函数、CTE、JSON 字段 |
| **缓存** | Redis (Lettuce) | 7.x | 高性能缓存 / Session / Token / AI 短期记忆，Lettuce 比 Jedis 性能更好 |
| **向量数据库** | ChromaDB | 1.5.9 | 轻量级向量库，Spring AI 原生支持，单机部署友好，`initialize-schema: true` 自动建集合 |

### 1.3 AI 相关

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| **大模型** | DeepSeek (OpenAI 兼容) | deepseek-chat | 高性价比，中文效果好，通过 OpenAI 兼容接口接入，切换模型成本极低 |
| **Embedding** | 智谱 embedding-2 | 1024 维 | 中文向量化效果好，OpenAI 兼容接口，成本低于 OpenAI |
| **文档解析** | Apache Tika | 2.9.1 | 支持 PDF / Word / Markdown / TXT / Excel 等多种格式，Apache 顶级项目 |
| **HTML 解析** | Jsoup | 1.17.2 | 资讯爬虫模块使用（已移除，保留依赖以备恢复） |

### 1.4 工具与文档

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|---------|
| **JSON** | FastJSON2 | 2.0.62 | 高性能 JSON 序列化/反序列化，支持 JSONPath |
| **API 文档** | springdoc-openapi | 3.0.3 | OpenAPI 3 规范，替代旧版 Swagger，与 Spring Boot 4.0 兼容 |
| **邮件** | spring-boot-starter-mail | — | JavaMailSender 异步发送，支持模板 |
| **定时任务** | Quartz | — | 企业级任务调度，支持 Cron 表达式、持久化、集群 |

## 三、技术选型深度解析

### 3.1 为什么选 Spring AI 而非 LangChain4j

| 维度 | Spring AI | LangChain4j |
|------|-----------|-------------|
| 与 Spring Boot 集成 | 原生深度集成 | 需要桥接 |
| 生态 | Spring 生态（Boot/Security/Cloud） | LangChain 生态 |
| API 风格 | Spring 风格（ChatClient/Advisor） | LangChain 风格 |
| 向量存储支持 | 原生支持 ChromaDB/Milvus/Pinecone 等 | 支持，但封装较重 |
| 学习曲线 | Spring 开发者零学习成本 | 需学习 LangChain 概念 |

本项目已深度使用 Spring 生态（Boot/Security/MyBatis），选 Spring AI 可无缝集成。

### 3.2 为什么选 DeepSeek 而非 OpenAI

| 维度 | DeepSeek | OpenAI |
|------|---------|--------|
| 价格 | 高性价比（约为 GPT-4 的 1/10） | 较贵 |
| 中文效果 | 优秀 | 良好 |
| 接口兼容 | OpenAI 兼容 | 原生 |
| 网络可达性 | 国内直连 | 需代理 |
| 切换成本 | OpenAI 兼容，切换只需改 base-url | — |

### 3.3 为什么选 ChromaDB 而非 Milvus

| 维度 | ChromaDB | Milvus |
|------|---------|--------|
| 部署复杂度 | 单机一行命令 | 需要集群 |
| Spring AI 支持 | 原生 | 原生 |
| 性能 | 单机够用 | 分布式高性能 |
| 适用场景 | 中小规模 | 大规模 |
| 运维成本 | 低 | 高 |

招标业务文档量中等（数千到数万文档），ChromaDB 单机足够。

### 3.4 双端点解耦方案

规范 11.4 锁定 chat=DeepSeek、Embedding=智谱 embedding-2，二者端点不同：

```
DeepSeek:  https://api.deepseek.com              (chat)
智谱:       https://open.bigmodel.cn/api/paas/v4/ (embedding)
```

Spring AI 的 OpenAI starter 中 `base-url` 和 `api-key` 是连接级共享的。解决方案：

```java
@Configuration
public class EmbeddingConfig {

    @Value("${zhipu.api-key}")
    private String zhipuApiKey;

    @Bean
    @Primary
    public OpenAiEmbeddingModel embeddingModel() {
        OpenAiApi api = OpenAiApi.builder()
            .baseUrl("https://open.bigmodel.cn/api/paas/v4/")
            .apiKey(zhipuApiKey)
            .build();
        return new OpenAiEmbeddingModel(api,
            MetadataMode.EMBED,
            OpenAiEmbeddingOptions.builder().model("embedding-2").build());
    }
}
```

`@Primary` 覆盖自动配置，让 `ChromaVectorStore` 注入这个自定义 Bean。chat 仍走 DeepSeek 自动配置。

## 四、版本锁定原则

### 4.1 SSOT 版本锁定

项目采用 **SSOT（唯一事实来源）** 原则，所有技术版本在开发规范 11.4 章节锁定，禁止随意升级：

| 技术栈 | 规范 11.4 锁定值 | 状态 |
|--------|-----------------|------|
| JDK | 21 | 已对齐 |
| Spring Boot | 4.0.6 | 已对齐 |
| Spring AI | 2.0.0 | 已对齐 |
| ORM | 原生 MyBatis + PageHelper 4.1.0 | 已对齐 |
| 大模型 | DeepSeek（OpenAI 兼容） | 已对齐 |
| Embedding | embedding-2（智谱，1024 维） | 已对齐 |
| 文档解析 | Apache Tika 2.9.1 | 已对齐 |

### 4.2 锁定理由

- 多人协作一致性：所有人用相同版本，避免"我这能跑你那不能跑"
- AI 生成代码可控：AI 编程工具按锁定版本生成代码
- 兼容性验证：版本组合已经过验证，避免版本冲突

## 六、技术风险与应对

| 风险点 | 说明 | 应对措施 |
|--------|------|---------|
| Spring AI 2.0 API 变动 | 较新版本，API 可能与文档示例有差异 | 以官方文档为准，先写最小 demo 验证 |
| Embedding 双端点 | chat 与 embedding 端点不同 | 自定义 EmbeddingConfig，@Primary 覆盖 |
| ChromaDB 版本兼容 | spring-ai-chroma 对版本有要求 | 用 latest，启动时 initialize-schema 验证连通 |
| Spring Boot 4.0 稳定性 | 主版本升级可能有 breaking change | 依赖 RuoYi 已验证的兼容性 |
| SSE 连接管理 | 高并发下资源泄漏 | 单用户单连接 + 心跳 + 超时关闭 |
