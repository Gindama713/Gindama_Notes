# 使用教程

本文档提供 PGI 系统的完整使用指南，覆盖环境准备、后端配置、前端启动、核心功能使用、生产部署、常见问题排查。按顺序操作即可从零跑通系统。适合实施人员、最终用户和新成员。

## 一、环境准备

### 1.1 软件要求

| 软件 | 版本 | 用途 | 下载说明 |
|------|------|------|---------|
| JDK | **21** | 后端编译运行 | OpenJDK 21 LTS，IDEA 内置或官网下载 |
| Maven | 3.9+ | 后端构建 | 项目未内置 mvnw，需自行安装 |
| MySQL | 8.0 | 业务数据库 | 8.4 也可，需支持 utf8mb4 |
| Redis | 7.x | 缓存/Session/Token | 7-alpine 即可 |
| ChromaDB | latest | 向量数据库（RAG） | Docker 或 Python 安装 |
| Node.js | 20+ | 前端构建 | LTS 版本 |
| IDEA | 推荐 | 后端 IDE | Ultimate 或 Community + 插件 |

### 1.2 克隆项目

```bash
git clone <项目仓库地址>
cd pgi
```

### 1.3 项目目录结构

```
pgi/
├── ruoyi-admin/          # 启动入口
├── ruoyi-common/         # 基础层
├── ruoyi-framework/      # 框架核心
├── ruoyi-system/         # 系统管理
├── ruoyi-quartz/         # 定时任务
├── ruoyi-bid/            # 招标业务
├── ruoyi-ai/             # AI 智能体
├── ruoyi-rag/            # RAG 知识库
├── ruoyi-notify/         # 消息通知
├── ruoyi-ui/RuoYi-Vue3/  # 前端
├── sql/                  # SQL 脚本
├── deploy/               # 部署配置
├── doc/                  # 文档
└── pom.xml               # 父 POM
```

## 二、后端配置（5 步）

### 第 1 步：MySQL 配置

#### 1.1 创建数据库

```sql
CREATE DATABASE IF NOT EXISTS pgi
DEFAULT CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

#### 1.2 导入 SQL（按顺序执行）

在 IDEA / DataGrip / DBeaver / 命令行中依次执行：

| 顺序 | SQL 文件 | 说明 |
|------|----------|------|
| 1 | `sql/ry_20260417.sql` | RuoYi 系统表 DDL + 初始化数据（用户/角色/菜单/字典） |
| 2 | `sql/quartz.sql` | Quartz 定时任务表 |
| 3 | `sql/pgi_menu.sql` | 菜单权限初始化（80+ 菜单项 + 角色关联） |
| 4 | `sql/dict_init.sql` | 字典数据初始化（pgi_* 系列字典） |

> [!warning] 注意
> `cleanup_generator_orphan.sql` 仅旧库升级用（清理代码生成器残留），**全新数据库请勿执行**，否则可能误删数据。

#### 1.3 修改数据库连接

打开 `ruoyi-admin/src/main/resources/application-druid.yml`：

```yaml
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    druid:
      master:
        url: jdbc:mysql://localhost:3306/pgi?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
        username: root
        password: 你的MySQL密码    # ← 改这里
      slave:
        enabled: false
```

将 `password` 改为你本地的真实 MySQL 密码。

### 第 2 步：Redis 配置

#### 2.1 启动 Redis

```bash
# 方式 A：本地安装启动
redis-server

# 方式 B：Docker 启动（推荐）
docker run -d -p 6379:6379 --name redis redis:7-alpine --requirepass 你的密码
```

#### 2.2 修改 Redis 配置

打开 `ruoyi-admin/src/main/resources/application.yml`，找到 Redis 配置段：

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      database: 4              # 使用 4 号库
      password: 你的密码        # ← 改这里，无密码则置空或注释
      timeout: 10s
      lettuce:
        pool:
          max-active: 8
          max-wait: -1ms
          max-idle: 8
          min-idle: 0
```

### 第 3 步：ChromaDB 启动

ChromaDB 是 AI 模块 RAG 功能依赖的向量数据库。

#### 方式 A：Docker 启动（推荐）

```bash
docker run -d -p 8000:8000 --name chromadb chromadb/chroma:latest
```

验证启动成功：

```bash
curl http://localhost:8000/api/v1/health
# 返回 {"heartbeat": ...} 即正常
```

#### 方式 B：Python 本地安装

适合没有 Docker 的环境：

```bash
# 确保已安装 Python 3.9+
python --version

# 安装 ChromaDB
pip install chromadb

# 启动服务
chroma run --host 127.0.0.1 --port 8000 --path "D:/chroma_data"
```

> 提示：可写一个 bat 启动脚本一键启动，参考 `deploy/start_chroma.bat`。

#### 确认 ChromaDB 配置

打开 `ruoyi-admin/src/main/resources/application-ai.yml`：

```yaml
spring:
  ai:
    vectorstore:
      chroma:
        client:
          host: http://localhost
          port: 8000
        collection-name: pgi_knowledge
        initialize-schema: true
```

一般不需要修改。ChromaDB 启动后会自动创建 `pgi_knowledge` 集合。

### 第 4 步：配置 DeepSeek API Key（可选）

> [!important] 重要
> `application.yml` 中 `spring.profiles.include: ai` 默认开启，后端启动时会加载 AI 模块配置并连接 ChromaDB。**即使不配置 DeepSeek API Key，也必须先启动 ChromaDB**，否则后端可能启动失败。

系统需要 DeepSeek 的 API Key 才能使用 AI 对话功能。打开 `application-ai.yml`：

```yaml
spring:
  ai:
    openai:
      base-url: https://api.deepseek.com
      api-key: your-api-key-here    # ← 在这里填入你的 API Key
      chat:
        options:
          model: deepseek-chat
          temperature: 0.7
          max-tokens: 4096
```

或通过**环境变量**注入（更安全）：

```bash
# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-你的key"

# Windows CMD
set DEEPSEEK_API_KEY=sk-你的key

# Mac / Linux
export DEEPSEEK_API_KEY=sk-你的key
```

> 如果没有 API Key，项目仍可正常启动和登录，但 AI 相关功能不可用。

#### 渐进式启动（跳过 AI 模块）

如果暂时不需要 AI 功能，最简单的做法是注释掉 `include: ai`：

```yaml
spring:
  profiles:
    active: druid
    # include: ai    # 暂时注释，跳过 AI 模块
```

这样后端启动不依赖 ChromaDB 和 DeepSeek，可先跑通基础招标功能。

### 第 5 步：启动后端

#### 5.1 IDEA 导入项目

- `File → Open →` 选择项目根目录 `pgi`
- IDEA 会自动识别 Maven 项目并下载依赖（需要几分钟，耐心等待）
- 确认 `Project SDK` 设置为 **JDK 21**（`File → Project Structure → Project → SDK`）

#### 5.2 启动主类

找到 `ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`，右键 → **Run 'RuoYiApplication'**。

#### 5.3 验证后端

浏览器访问：`http://localhost:8080`

如果看到提示页面，说明后端启动成功。后端默认端口 **8080**。

## 三、前端启动（2 步）

### 第 6 步：安装依赖

```bash
cd ruoyi-ui/RuoYi-Vue3
npm install
```

如果速度慢，可使用淘宝镜像：

```bash
npm install --registry=https://registry.npmmirror.com
```

### 第 7 步：启动前端

```bash
npm run dev
```

浏览器访问：`http://localhost`（或根据控制台提示的端口）

默认账号：`admin / admin123`

> [!info] 前后端代理说明
> 前端通过 Vite 代理转发接口请求：
> - `.env.development` 中 `VITE_APP_BASE_API = '/dev-api'`
> - `vite.config.js` 将 `/dev-api` 代理到 `http://localhost:8080`
>
> **如果你修改了后端端口，需同步修改 `vite.config.js` 中的 `baseUrl`。**

## 四、核心功能使用

### 4.1 招标业务操作

登录后通过左侧菜单操作：

| 菜单路径 | 功能 | 角色 | 关联模块 |
|---------|------|------|---------|
| 招标管理 → 项目管理 | 创建/提交/终止项目 | 代理机构、招标人 | ruoyi-bid |
| 招标管理 → 招标公告 | 发布/审核/撤回公告 | 代理机构、审核人员 | ruoyi-bid |
| 招标管理 → 招标文件 | 上传/备案招标文件 | 代理机构、审核人员 | ruoyi-bid |
| 交易管理 → 投标管理 | 提交/撤回投标 | 投标方 | ruoyi-bid |
| 交易管理 → 评标管理 | 评标打分/完成 | 评标专家、评标组长 | ruoyi-bid |
| 交易管理 → 中标管理 | 发布/确认/取消中标 | 代理机构、招标人 | ruoyi-bid |
| 交易管理 → 资质管理 | 资质登记/审核/续期 | 投标方、审核人员 | ruoyi-bid |
| 交易管理 → 保证金 | 缴纳/退还/没收 | 投标方、代理机构 | ruoyi-bid |
| 交易管理 → 场地预约 | 预约/取消场地 | 代理机构 | ruoyi-bid |
| 审核管理 | 各类审核任务 | 审核人员 | ruoyi-bid |

完整业务流程见 [[招标全流程]]。

#### 操作示例：创建项目

1. 代理机构登录，进入"招标管理 → 项目管理"
2. 点击"新增"按钮
3. 填写项目信息：
   - 项目编号（唯一）
   - 项目名称
   - 预算金额（>0）
   - 投标截止时间（需 24h 后）
   - 所属部门（自动填充）
4. 点击"保存"，项目状态为 `DRAFT`
5. 点击"提交注册"，状态变为 `REGISTERED`

### 4.2 AI 智能对话

#### 进入 AI 对话

1. 登录后进入 **AI 智能体** 菜单
2. 点击"新建会话"
3. 在输入框输入问题，例如：

```
帮我查一下 PGI-2026-001 项目的进展
```

4. AI 流式返回结果，工具调用以卡片形式展示

#### 典型对话场景

| 场景 | 用户输入 | AI 行为 |
|------|---------|---------|
| 查询项目 | "帮我查一下 XX 项目的进展" | 调用 SearchProjectTool，返回项目列表 |
| 获取详情 | "PGI-2026-001 项目详情" | 调用 GetProjectDetailTool，返回详情 |
| 检索文档 | "检索一下招投标相关法规" | 调用 SearchRagDocTool（需先上传知识库文档） |
| 添加进度（写操作） | "把 PGI-2026-001 进度更新为评标中" | 调用 AddProgressTool，弹窗确认后执行 |
| 查询资质 | "我们公司的资质状态" | 调用 CheckQualificationTool |

#### 写操作确认流程

写操作工具（如添加进度、提交资质）执行前会弹窗确认：

1. AI 识别需要执行写操作
2. 创建 `pgi_ai_action_record`（confirm_status='0'），暂停执行
3. 前端弹窗："确认更新项目进度？"
4. 用户点击"确认" → 执行工具，记录 before/after 快照
5. 用户点击"拒绝" → 取消执行，记录拒绝原因

#### 操作回滚

用户可对已执行的写操作调用回滚：
1. 在对话历史中找到对应操作
2. 点击"撤销"按钮
3. 系统根据 before 快照恢复数据

详见 [[AI智能体]] 和 [[工具调用体系]]。

### 4.3 RAG 知识库

#### 上传知识库文档

1. 进入 **知识库管理** 菜单（需管理员权限）
2. 点击"创建知识库"，填写名称和描述
3. 进入知识库详情，点击"上传文档"
4. 选择文件（支持 PDF / Word / Markdown / TXT）
5. 系统自动处理：上传 → 解析（Tika）→ 分块（500 字重叠 50）→ 向量化（智谱 embedding-2）→ 存储（ChromaDB）

#### 文档状态流转

| 状态 | 含义 |
|------|------|
| UPLOADED | 已上传，待处理 |
| PROCESSING | 正在解析分块向量化 |
| READY | 处理完成，可被 AI 检索 |
| FAILED | 处理失败（可重试，<3 次） |
| DELETED | 已删除（同步删除向量） |

#### 使用知识库

文档状态变为 `READY` 后，AI 对话即可基于该文档回答问题：

```
用户：我们公司的招标制度里对保证金有什么规定？
AI：[调用 SearchRagDocTool 检索知识库]
    根据您上传的《企业招标管理制度》第 5.3 节，
    保证金金额为项目预算的 2%，未中标方在评标完成后
    7 个工作日内自动退还...
```

详见 [[RAG知识库]]。

## 六、生产部署

### 6.1 Docker Compose 一键部署

生产环境推荐用 Docker Compose：

```bash
cd deploy
docker-compose up -d
```

`deploy/docker-compose.yml` 定义 5 个服务：

| 服务 | 镜像 | 端口 | 依赖 |
|------|------|------|------|
| mysql | mysql:8.0 | 3306 | — |
| redis | redis:7-alpine | 6379 | — |
| chroma | chromadb/chroma:latest | 8000 | — |
| app | Spring Boot JAR | 8080 | mysql / redis / chroma |
| nginx | nginx:alpine | 80 | app |

### 6.2 Nginx 配置要点

- 反向代理 `/prod-api` → `app:8080`
- 前端静态资源服务
- **SSE 缓冲关闭**（`proxy_buffering off`）— 流式对话必须

详见 [[部署方案]]。

## 七、常见问题

遇到问题先看 [[常见问题排查]]，90% 的报错都能快速定位。高频问题：

| 问题 | 原因 | 解决 |
|------|------|------|
| `Access denied for user 'root'` | MySQL 密码不对 | 改 `application-druid.yml` |
| `Redis connection refused` | Redis 未启动 | 启动 Redis 或检查密码 |
| `ChromaDB connection refused` | ChromaDB 未启动 | 启动 ChromaDB 或注释 `include: ai` |
| `Java: invalid source release: 21` | JDK 版本不对 | IDEA 设置 JDK 21 |
| AI 无响应 | API Key 未配置 | 检查 DeepSeek API Key |
| 状态流转失败 | 违反业务规则 | 对照 [[业务规则体系]] 检查前置条件 |
| 前端页面空白 | 后端未启动 | 先启动后端 |
| 文件上传失败 | 文件过大/类型不符 | ≤100MB，检查类型白名单 |

## 八、文件上传路径配置

系统默认上传文件保存目录在 `application.yml` 中配置：

```yaml
ruoyi:
  profile: D:/ruoyi/uploadPath    # Windows
  # profile: /home/ruoyi/uploadPath    # Linux
```

后续可集成云存储（OSS/COS）。

## 九、Token 密钥配置

`application.yml` 中 `token.secret` 默认为弱密钥，**生产环境务必修改**：

```yaml
token:
  header: Authorization
  secret: 请替换为一串足够长的随机字符串
  expireTime: 30    # 分钟
```
