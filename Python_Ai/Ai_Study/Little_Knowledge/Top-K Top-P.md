## LLM 生成里的 Top-K

- K 越小 → 越保守、越确定
- K 越大 → 越多样、越有创意
- K = 1 → 永远选概率最高的，叫贪心解码

## LLM 生成里的 Top-P

- P 越小 → 越保守
- P 越大 → 越多样

很多模型支持两个一起用，通常是：
1. 先按 Top-K 筛掉太离谱的词
2. 再按 Top-P 从剩下的里面筛

比如 Top-K=50，Top-P=0.9：
> 先取概率最高的 50 个词，再从这 50 个里，按累计概率 0.9 截断。

这样既不会选到太离谱的词，又保留了一定多样性。

| 参数              | 作用           | 怎么影响                   |
| --------------- | ------------ | ---------------------- |
| [[temperature]] | 调整概率分布的平滑程度  | 高温让低概率词也有机会，低温让高概率词更突出 |
| Top-K           | 硬截断，只留 K 个   | 控制候选数量                 |
| Top-P           | 动态截断，留累计概率 P | 控制候选范围                 |
|                 |              |                        |

**Temperature 改的是“概率长什么样”，Top-K/Top-P 改的是“从哪些词里选”。**

## [[4_RAG 检索增强生成]] 检索里的 Top-K

在 RAG 里，Top-K 就是：
> **向量检索返回最相似的 K 个文档块。**

Top-K 不是拍脑袋，它取决于：

| 因素               | 影响                                                          |
| ---------------- | ----------------------------------------------------------- |
| **Chunk 大小**     | chunk 越小，需要召回越多条才能覆盖同样信息；chunk 越大，召回条数可以少                   |
| **文档总量**         | 文档越多，相关内容的绝对数量可能越多，召回 K 要相应增大                               |
| **问题类型**         | 事实型问题可能 1～2 条就够；综述型问题需要更多上下文                                |
| [[Embedding]] 模型 | 模型召回质量高，K 可以小；质量差，需要大 K 兜底                                  |
| **是否用 Reranker** | 有 Reranker：召回可以大（50～100），最终取 5～10；没 Reranker：召回和最终差不多，K 要谨慎 |
| **LLM 上下文窗口**    | 窗口小，最终 K 不能大；窗口大，可以多塞                                       |
| **延迟和成本**        | K 越大，检索越慢、LLM 输入 token 越多、越贵                                |
| **评估指标**         | 用 Recall@K 看拐点，找到“再增加 K 收益很小”的位置                            |
