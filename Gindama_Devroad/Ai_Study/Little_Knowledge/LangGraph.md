**是 LangChain 团队推出的一个专门用来构建“有状态、多步骤、带循环”的 Agent 工作流框架。**

一句话：

> **[[LangGraph]]是搭积木，LangGraph 是画流程图。**
> **它让你用“状态机”的思维来设计复杂的 AI Agent。**

## 一、为什么需要 LangGraph？

你之前学过 ReAct：
思考 → 行动 → 观察 → 再思考 → ... → 回答
这是一个**循环**。

如果你用 LangChain 的 Chain，它是**直线**的：
A → B → C → 结束

**但 Agent 不是直线，它会循环、分支、回退。**
比如：
- 工具调用失败 → 重试
- 检索结果不够 → 改写查询再检索
- 用户插话 → 中断当前流程
- 多步规划 → 每一步都可能走不同分支

**LangChain 的 Chain 表达不了这种复杂流程，LangGraph 就是来解决这个问题的。**

## 五、LangGraph 的杀手锏

### 1. Checkpoint（断点续跑）

Agent 跑到一半崩了，可以从上次的状态恢复，不用从头来。
### 2. Human-in-the-loop（人工介入）

Agent 执行到关键步骤，可以暂停，等人审批后再继续。
比如：

Agent 准备删除文件
   ↓
暂停，弹出确认框
   ↓
用户点“同意” → 继续
用户点“拒绝” → 走另一条路

### 3. 多 Agent 协作

多个 Agent 各自是一个子图，互相调用。
规划 Agent → 执行 Agent → 审查 Agent → 修正 Agent

### 4. 流式输出

每个节点的输出可以实时推给前端。
